# Internationalisation (fr / en)

The site is a static export (`output: "export"`): there is no proxy or server, so no server-side
`Accept-Language` detection. Each language has its own pages: `/fr`, `/en`, `/fr/editor`,
`/en/editor`. The root `/` redirects on the client (saved preference, then browser language,
otherwise `fr`). On Vercel, `vercel.json` also redirects `/` based on `Accept-Language`.

There is no i18n library: the core fits in `i18n/` (React provider, typed translator,
locale-preserving navigation).

## Where things are

| File | Purpose |
|---|---|
| `i18n/routing.ts` | locales, default locale, language labels |
| `i18n/translator.ts` | `createTranslator`, `{name}` interpolation, plural suffix |
| `i18n/provider.tsx` | `useLocale()`, `useTranslations("namespace")` |
| `i18n/navigation.tsx` | `Link`, `useRouter`, `usePathname`: paths **without** the locale prefix |
| `i18n/detect.ts` | remembered choice (localStorage) and detection for `/` |
| `messages/fr.json`, `messages/en.json` | all texts, grouped by namespace |
| `scripts/check-i18n.mjs` | `pnpm i18n:check` |

## Conventions

- `messages/fr.json` is the typing reference: an unknown key in `t("…")` or a key missing from
  another language makes `pnpm typecheck` fail.
- Static data (field schemas, templates, export formats, slots) carries **no** text, only keys
  (`labelKey`, `nameKey`…), resolved at render time.
- Code in `lib/` does not import React: it throws errors carrying a `code` (`ImageError`,
  `ExportError`, `CaptureError`), and the calling component translates them.
- Plurals: two keys, `xOne` / `xOther`, picked with `pluralSuffix(locale, n)`.
- The editor's sample texts (`defaults`) are translated when the language changes, but a field
  the user has edited is never overwritten (`localizeContent`).
- `pnpm i18n:check` also fails on unused keys and on accented text hard-coded in components.

## Adding a language

1. Add the code to `locales`, `LOCALE_NAMES` and `OPEN_GRAPH_LOCALES` (`i18n/routing.ts`).
2. Create `messages/<code>.json` by copying `fr.json`, then add it to `MESSAGES`
   (`i18n/messages.ts`).
3. Run `pnpm typecheck && pnpm i18n:check`.

## Known limitations

- `app/manifest.ts` is unique: its description and language stay in French.
- Switching language recreates the page, so any local state is lost. State that must survive
  (such as the editor's open panel) has to live in the store.
