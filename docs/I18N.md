# Internationalisation (fr / en)

Le site est un export statique (`output: "export"`) : pas de proxy ni de serveur, donc pas de
détection `Accept-Language` côté serveur. Chaque langue a ses propres pages : `/fr`, `/en`,
`/fr/editor`, `/en/editor`. La racine `/` redirige côté client (préférence enregistrée, puis
langue du navigateur, sinon `fr`).

Aucune bibliothèque i18n : le noyau tient dans `i18n/` (provider React, traducteur typé,
navigation qui garde la langue).

## Où est quoi

| Fichier | Rôle |
|---|---|
| `i18n/routing.ts` | langues, langue par défaut, libellés des langues |
| `i18n/translator.ts` | `createTranslator`, interpolation `{nom}`, suffixe de pluriel |
| `i18n/provider.tsx` | `useLocale()`, `useTranslations("namespace")` |
| `i18n/navigation.tsx` | `Link`, `useRouter`, `usePathname` : chemins **sans** préfixe de langue |
| `i18n/detect.ts` | choix mémorisé (localStorage) et détection pour `/` |
| `messages/fr.json`, `messages/en.json` | tous les textes, groupés par namespace |
| `scripts/check-i18n.mjs` | `pnpm i18n:check` |

## Conventions

- `messages/fr.json` fait référence pour le typage : une clé inconnue dans `t("…")` ou une clé
  manquante dans une autre langue fait échouer `pnpm typecheck`.
- Les données statiques (schéma des champs, templates, formats d'export, emplacements) ne
  portent **pas** de texte mais des clés (`labelKey`, `nameKey`…), résolues au rendu.
- Le code de `lib/` n'importe pas React : il lève des erreurs avec un `code`
  (`ImageError`, `ExportError`), et le composant appelant traduit.
- Pluriels : deux clés `xOne` / `xOther`, choisies avec `pluralSuffix(locale, n)`.
- Les textes d'exemple de l'éditeur (`defaults`) se traduisent au changement de langue, mais
  un champ modifié par l'utilisateur n'est jamais écrasé (`localizeContent`).

## Ajouter une langue

1. Ajouter le code dans `locales`, `LOCALE_NAMES` et `OPEN_GRAPH_LOCALES` (`i18n/routing.ts`).
2. Créer `messages/<code>.json` en copiant `fr.json`, puis l'ajouter à `MESSAGES`
   (`i18n/messages.ts`).
3. Lancer `pnpm typecheck && pnpm i18n:check`.

## Limites connues

- `app/manifest.ts` est unique : sa description et sa langue restent en français.
- Changer de langue recrée la page : tout état local est perdu. L'état à conserver (comme le
  panneau ouvert de l'éditeur) doit vivre dans le store.
